# 기보를 서버에 남기기

브라우저에만 쌓이던 기보를 **로그인한 사람의 것은 서버에도** 남긴다. 서버 쪽 설계와
주소는 `janggi-server` 저장소의 `GAMES.md` 에 있다. 여기서 되풀이하지 않는다.

이 파일은 **한 대화에 끝나지 않는 작업의 계획**이다. 다 끝나면 지운다.

## 정한 것

**로그인하지 않아도 기보는 지금처럼 쌓인다.** 로그인한 뒤에 새로 둔 판만 서버로
올린다. 2026-10-14 에 정했다.

고려한 셋 중에서 골랐다.

|                       | 하는 일                                   | 왜 안 골랐나                                                                                                                                              |
| --------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 묻고 합치기           | 로그인할 때 "기기에 N판 있는데 올릴까요?" | 합치기·중복·거절 처리가 이 일에서 가장 복잡한 부분이다                                                                                                    |
| 로그인 없으면 안 쌓기 | 로그인만 기보를 가진다                    | **이미 쓰는 사람의 기보가 사라진다.** 들어온 39명 중 12명이 한 판을 끝냈고, 구글 동의 화면까지 거칠 사람은 그보다 훨씬 적다. 복기를 벽 뒤로 보내는 셈이다 |
| **고른 것**           | 로컬은 그대로. 로그인 뒤 새 판만 올린다   | -                                                                                                                                                         |

**비용을 알고 고른다.** 폰에서 로그인하면 그 뒤에 둔 판만 PC 에서 보인다. 옛 판은
폰에만 남는다. 나중에 기보 탭에 "이 기기의 N판 올리기" 단추로 붙일 수 있다 -
로그인 흐름에 끼워 넣지 않으면 훨씬 단순하다.

## 변경의 종류

**새 확인 방법이 필요한 변경.** DB 구조와 데이터를 건드리지 않고, 비밀 정보를 다루지
않는다. 로그인 상태를 읽기만 한다 - 쿠키를 만들고 검사하는 일은 전부 서버에 있다.

**배포는 따로 본다.** 배포는 되돌릴 수 없는 변경이라, 아래 "배포" 절의 되돌리는
방법을 지킨다.

## 올리는 자리를 한 곳으로 둔다

판이 저장되는 자리가 둘이다.

| 자리                                                   | 언제           |
| ------------------------------------------------------ | -------------- |
| `src/App.tsx` 의 `setGames(upsertGame(...))`           | 판이 끝났을 때 |
| `src/hooks/useGames.ts` 의 `setGames(upsertGame(...))` | 복기를 돌린 뒤 |

**두 군데에 "서버에도 올려라" 를 각각 붙이지 않는다.** 같은 판단이 두 곳으로 갈라진다.
대신 **목록이 바뀌는 것을 한 곳에서 보고** 올린다. 판 끝남과 복기 끝남이 같은 길로
처리되고, 서버의 덮어쓰기(같은 판 번호는 한 줄로)가 그것을 받는다.

**"로그인 뒤에 둔 판" 을 어떻게 아나** - 앱이 뜰 때의 목록을 기준선으로 잡고, 그
뒤에 새로 생기거나 바뀐 판만 올린다. 로그인은 구글로 쪽을 옮겼다 돌아오는 일이라
앱이 다시 뜨고, 그래서 **로그인 전에 둔 판은 기준선에 들어가 올라가지 않는다.**
시각을 따로 적어 둘 필요가 없다.

## 바꿀 것

| 파일                                    | 무엇                                               |
| --------------------------------------- | -------------------------------------------------- |
| `src/server/api.ts` (새 파일)           | 서버와 말하는 한 자리. CSRF 토큰 주고받기도 여기만 |
| `src/hooks/useServerGames.ts` (새 파일) | 로그인 상태(`/me`) + 올리기·목록·지우기            |
| `src/components/games/GameBar.tsx`      | 로그인·로그아웃 줄                                 |
| `src/components/games/GameList.tsx`     | "이 기기에만 있음" 표시                            |
| `src/App.tsx`                           | 위 둘을 잇기                                       |
| `CLAUDE.md`                             | 폴더 지도에 `server/` 한 줄                        |

`src/server/` 를 새로 두는 까닭 - `src/janggi/` 는 규칙만 있어서 네트워크를 몰라야
하고, `src/report/` 는 오류·제보·측정 자리다. 섞으면 의존이 양쪽으로 흐른다.

## 안 바꿀 것

- 로그인하지 않은 사람의 화면과 저장 (지금과 똑같이 돈다)
- `localStorage` 한도 100판, `archive.ts` 의 모양·검사
- 기보 파일 가져오기·내보내기
- 머리말 - 폭 320 에서 자리가 없다. 로그인 줄은 기보 탭 안에 둔다
- 이메일·이름 표시. "로그인됨" 만 보인다 (2026-10-13 에 정했다)

## 두 쪽으로 나눈다

### 1쪽 - 올리기

- 기보 탭에 로그인 단추(`/api/oauth2/authorization/google` 로 쪽 이동), 로그아웃
- 로그인한 뒤 새로 생기거나 바뀐 판을 올린다
- 목록에 "이 기기에만 있음" 표시. **올리기가 실패했을 때도 같은 표시가 나온다** -
  조용히 넘어가지 않으면서 화면을 하나 더 만들지 않는 길이다

### 2쪽 - 받기

- 로그인 상태면 서버 목록을 가져와 섞는다
- 서버에만 있는 판 열기 (기기를 바꿔도 보이는 것이 이 기능의 값이다)

**지우기는 넣지 않는다.** 이 앱에는 기보를 지우는 길이 아예 없다 - `useGames` 의
`reset` 은 보던 자리를 되돌리는 것이지 판을 지우는 것이 아니다. 부르는 데가 없는
코드를 만들지 않는다. 100판이 넘을 때 오래된 것을 버리는 것은 **기기 사정**이라
서버까지 지우면 안 된다. 서버에 500판을 두는 까닭이 그것이다.

**서버 요약에 마지막 국면(`lastFen`)을 더했다.** 목록 카드가 끝난 판을 작은 그림으로
보여 주는데, 서버에만 있는 판은 내용이 없어 그릴 수가 없었다. JSONB 에서 한 칸만
뽑으므로 내용 전체가 끌려오지 않고, 500판이면 45KB쯤 는다. 안 하면 판 하나하나를
또 불러야 한다 - 스무 판이면 스무 번이다.

**1쪽만 배포하지 않는다.** 사람 눈에는 단추만 생기고 달라지는 것이 없다.

## 완료 조건

로컬에서 실행해 확인한다. 서버는 `localhost:8080`, 화면은 미리보기다 -
`vite.config.ts` 가 `/api` 를 서버로 넘긴다(Vercel 되돌림과 같은 모양).

| 확인                            | 어떻게                                            |
| ------------------------------- | ------------------------------------------------- |
| 타입·테스트·빌드                | `npx tsc -b` · `npx vitest run` · `npm run build` |
| 로그인 안 한 화면이 그대로인가  | 판을 두고 기보 탭에 남는지                        |
| 로그인한 뒤 새 판이 올라가나    | 서버 DB 줄 수                                     |
| 로그인 전 판이 안 올라가나      | 서버 DB 줄 수 (늘지 않아야 한다)                  |
| 복기를 돌린 뒤 덮어써지나       | 서버의 수 개수가 바뀌는지                         |
| 올리기가 실패하면 표시가 나오나 | 서버를 끄고 판을 끝내 본다                        |
| 폰 폭 320·360·375·390           | 두 탭 다, 가로 스크롤 없음                        |

**로그인된 상태는 쿠키를 만들어 넣어 확인한다.** 로컬 서버를 띄울 때 서명 열쇠를
임시값으로 주고 같은 값으로 쿠키를 만든다. `.env` 의 값은 열지 않는다.

**로컬에서 확인되지 않는 것 하나** - 진짜 구글 왕복. `redirect_uri` 가 배포 주소로
못박혀 있다. 가짜 구글로 끝까지 돌리는 검사(서버 쪽 `LoginFlowTest` 7개)가 그 길을
보고, 배포 뒤에 실제 왕복을 한 번 확인한다.

## 배포

2쪽까지 끝나고, 위 확인을 다 하고, 사용자가 로컬에서 눈으로 본 뒤에 한다.

**되돌리는 방법** - Vercel 대시보드에서 앞 배포로 되돌린다(즉시). 서버는 건드리지
않으므로 되돌릴 것이 없다. **이미 올라간 기보는 남는다** - 되돌려도 서버의 줄은
그대로이고, 그건 사람이 지우라고 한 적 없는 자료라 지우지 않는다.

**줄일 수 없는 피해** - 없다. 기보는 올려도 브라우저에 그대로 남는다. 서버 쪽이
잘못되어도 기기의 기보는 잃지 않는다.

## 로컬에서 확인한 것 (2026-10-14, 1쪽)

브라우저(크로미움 헤드리스) + 미리보기(4173) + 로컬 서버(8080) + 로컬 Postgres(5434).
로그인은 서명 쿠키를 직접 만들어 넣었다. 임시 열쇠로 서버를 띄우고 같은 값으로 만든
것이라 `.env` 는 열지 않았다.

| 확인                       | 결과                                                  |
| -------------------------- | ----------------------------------------------------- |
| 타입 · 테스트 282개 · 빌드 | 통과                                                  |
| 로그인 안 한 화면          | "기보가 이 기기에만 남습니다" + 구글 로그인 링크      |
| 로그인 전에 둔 판          | 서버 0줄 - 안 올라간다                                |
| 로그인한 뒤 끝낸 판        | 바로 올라간다                                         |
| 복기를 돌린 뒤             | 같은 줄이 덮어써진다(줄 수 그대로, `reviewed` 채워짐) |

| 서버가 돌아온 뒤           | 다음 판이 끝날 때 **밀린 판까지 같이** 올라간다       |
| 로그아웃                   | 쿠키 둘과 올린 기록이 지워진다                        |
| 폭 320 · 360 · 375 · 390   | 가로 스크롤 없음                                      |

**로컬에서 안 본 것** - 진짜 구글 왕복. 위 "완료 조건" 에 적은 까닭 그대로다.

## 여기서 찾은 것 셋

**① 한 판 올릴 때마다 적으면 두 번째 판이 어긋난다.** 적을 때마다 다시 그려지고, 그
바람에 올리던 쪽이 "그만두라" 는 신호를 받는다. **올라갔는데 적히지 않은** 판이 생겨
화면에 "이 기기에만 있음" 이 남았다. 모아 두었다가 한 번에 적는 것으로 고쳤다.

**② 저장 열쇠에 접두사를 두 번 붙였다.** `usePersisted` 가 `janggi:` 를 붙이는데
열쇠에도 붙여서 `janggi:janggi:uploaded` 가 됐다. 돌아가기는 해서 화면으로는 안
보였다.

**③ 로그아웃했다가 다시 로그인하면 표시가 거짓이 된다.** 로그아웃이 올린 기록을
지우므로(다음 사람이 로그인할 수 있다), 서버에 있는 판도 "이 기기에만 있음" 이 된다.
**2쪽에서 서버 목록을 받아 오면 바로잡힌다.** 1쪽만 따로 배포하지 않는 까닭이 하나 더
생긴 셈이다.

## 로컬에서 확인한 것 (2026-10-14, 2쪽)

"다른 기기" 를 흉내 냈다 - 서버에만 판을 하나 넣고, 브라우저 저장소는 비운 채로 열었다.

| 확인 | 결과 |
| --- | --- |
| 서버 검사 120개 · 프런트 검사 295개 · 빌드 | 통과 |
| 서버에만 있는 판이 목록에 뜨나 | 뜬다. "다른 기기에서 둔 판" 이 붙는다 |
| 그 판의 작은 그림이 그려지나 | 그려진다(요약의 `lastFen` 으로) |
| 눌러서 열리나 | 열린다. 되짚기 단추가 선다 |
| 연 뒤에 기기 목록에 들어가나 | 들어간다(국면 3개 그대로) |
| 받은 판을 도로 올리지 않나 | 안 올린다(받을 때 지문을 같이 적는다) |
| 로그아웃 뒤 거짓 표시 | **고쳐졌다.** 서버 목록이 기록을 다시 채운다 |
| 폭 320 | 가로 스크롤 없음. 로그인 줄은 말줄임으로 들어간다 |

## 2쪽에서 찾은 것 셋

**① 서버에서 온 판 하나가 목록 전체를 죽였다.** 끝났을 때의 판(`lastFen`)을 그리다
터지면 기보 탭이 통째로 안 보인다. 기기에 있던 판은 우리 엔진이 만든 것이라 괜찮았는데,
**서버에서 오는 값은 그렇지 않다.** 못 읽으면 그 카드의 그림만 비우도록 고쳤다.

**② 받아서 바로 열려고 하면 끝없이 받는다.** 목록에 넣은 것은 한 박자 뒤에 반영되는데,
그 자리에서 열려고 하니 "없다" 가 되고 다시 받으러 갔다. **서버의 분당 한도(30)가
끊어 줘서** 멈췄다 - 문지기가 이 버그를 막았다. 받은 뒤 다음 그림에서 열도록 고쳤다.

**③ 검사가 두 번 "no tests" 로 끝났다.** 16개 파일이 다 실패로 나오는데 다시 돌리면
295개가 통과한다. **까닭을 모른다.** 빌드 직후라서 그런가 하고 그대로 재현해 봤는데
통과했다. 확인 안 된 채로 적어 둔다.
