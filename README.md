# 장기 AI

급수를 골라 장기 AI(세계 최강 장기 엔진)와 한 판 두고, 끝난 판을 한 수씩 되짚으며
AI 에게 복기를 받는다.

처음에는 Yixin-Board 를 장기로 옮긴 분석 도구라 이름이 '장기 분석판' 이었다. 판 편집·
실시간 분석을 하던 분석 탭을 빼고 나니 하는 일(AI 와 두고 복기하기)과 맞지 않아서,
장기와 AI 가 같이 드러나는 이름으로 바꿨다.

엔진은 **Fairy-Stockfish** 를 브라우저(WebAssembly)에서 돌리고, 장기 전용
NNUE 신경망(`janggi-9991472750de.nnue`, 기존 평가함수 대비 +1128 Elo)을 얹었다.
프로 기사보다 강하다.

화면은 탭 둘이다.

| 탭 | 하는 일 |
|---|---|
| **대국** | 급수를 골라 AI와 둔다 |
| **기보** | 지난 판 목록. 한 판을 골라 한 수씩 되짚고 복기한다 |

판 편집·FEN·실시간 분석을 하던 **분석** 탭은 뺐다. 엔진과 한 판 두러 온 사람에게는
쓸 일이 없는 화면이었다. 필요하다는 말이 나오면 되살린다(되살릴 기준 커밋은
[docs/DECISIONS.md](docs/DECISIONS.md) 의 '분석 탭을 뺐다').

판이 화면 높이를 꽉 채우고, 대국자 카드는 오른쪽 칸 맨 위에 선다(폰은 판 위아래).
자세한 것은 [화면 배치](#화면-배치) 참고.

## 시작하기

```bash
npm install
npm run dev      # http://localhost:5173
```

`npm run dev` 는 실행 전에 `scripts/fetch-engine.mjs` 를 돌려서 엔진 파일을
`public/engine/` 에 채운다. 처음 한 번만 약 13MB(엔진 1.6MB + 신경망 11.3MB)를
받고, 그 뒤로는 있는 파일을 쓴다. 이 파일들은 용량 때문에 저장소에 넣지 않는다.

> **신경망 받기가 실패하면** — 신경망은 남의 구글 드라이브 링크에서 받는다.
> 링크가 깨졌다면 <https://fairy-stockfish.github.io/nnue/> 에서
> `janggi-9991472750de.nnue` 를 직접 받아 `public/engine/` 에 넣으면 된다.
> 파일 이름은 그대로 두어야 한다.

```bash
npm test          # 순수 로직 테스트 (브라우저·엔진 없이)
npm run build     # 프로덕션 빌드
npm run preview   # 빌드 결과를 헤더까지 갖춰서 확인
npm run verify-engine   # 엔진만 따로 점검 (브라우저 없이)
```

### 환경 변수

| 이름 | 무엇 |
| --- | --- |
| `VITE_FEEDBACK_URL` | 제보를 받을 곳(구글 폼 같은 것)의 주소 |
| `VITE_FEEDBACK_ENTRY` | 그 폼에서 '환경' 을 받는 칸의 이름표(`entry.NNN`) |

`.env.local` 에 넣는다(`.env*` 는 `.gitignore` 에 들어 있다).

```
VITE_FEEDBACK_URL=https://docs.google.com/forms/d/e/.../viewform
VITE_FEEDBACK_ENTRY=entry.1007014165
```

**이름표를 얻는 법** — 구글 폼의 `⋮` → **미리 채워진 링크 가져오기** → '환경' 칸에만 아무
글자를 넣고 링크를 받으면 주소 끝에 `entry.1007014165=테스트` 처럼 붙어 있다. 그 `entry.NNN`
부분이다. 이름표가 없으면 버튼은 빈 폼만 연다.

**비워 두면 제보 버튼이 아예 뜨지 않는다.** 눌러도 갈 데가 없는 버튼을 두지
않으려는 것이다. 값은 빌드에 그대로 박히므로 비밀이 아닌 주소만 넣는다.

## 반드시 알아야 할 제약: COOP/COEP

엔진은 멀티스레드 탐색에 `SharedArrayBuffer` 를 쓰고, 브라우저는 아래 두 헤더가
있어야만 그걸 허용한다.

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

`vite.config.ts`(개발·미리보기)와 `vercel.json`(배포)에 이미 넣어뒀다. 파일을
그냥 열거나(`file://`) 헤더 없는 정적 서버에 올리면 **엔진이 시작되지 않는다.**
같은 이유로 글꼴(Pretendard)은 외부 서버에서 받지 않고 npm 패키지를 번들에 넣어
앱과 같은 출처에서 준다(`src/styles/index.css`).

올릴 곳을 고를 때 이 제약이 갈린다.

| 호스팅 | 가능 여부 | 비고 |
|---|---|---|
| Vercel | ✅ | `vercel.json` 이 이미 준비돼 있다 |
| Netlify / Cloudflare Pages | ✅ | 헤더 설정을 직접 옮겨야 한다 |
| **GitHub Pages** | ❌ | **응답 헤더를 지정할 수 없다** |

GitHub Pages 는 커스텀 헤더를 붙일 방법이 없어서 이 앱이 돌아가지 않는다.
굳이 쓰려면 `coi-serviceworker` 같이 서비스 워커로 헤더를 흉내 내는 우회가 필요하다.

## 기능

### 대국

**급수를 골라 둔다.** 18급부터 9단까지 27단계를 드롭다운에서 고른다. 얼마나
기다려야 하는지 모르는 것이 다른 장기 앱에서 가장 많이 나오는 불만이라, 한 수에
걸리는 어림 시간을 이름 옆에 적는다(`9단 — 한 수 약 20초`).

다만 **기다릴 일이 있는 급수에만** 적는다. 27개 중 19개(18급~1단)가 한 수에 1초를
넘지 않아서 전부 "1초 안" 으로 똑같이 적혔었다. 같은 말이 열아홉 번 반복되면 읽지
않게 되고, 정작 20초를 기다려야 하는 9단도 같은 자리에 적혀 눈에 띄지 않는다.

드롭다운은 **늘 칸 바로 아래로, 8줄까지만** 펼친다. 브라우저 기본 셀렉트였을 때는
아래 자리가 모자라면 위로 뒤집혀 열렸고 27단계가 화면 높이만큼 길게 펼쳐졌다.
고른 급수의 설명 줄(`포진 비슷한 것을 갖춘다`)은 뺐다. 목록은 이름만 보고 고르고,
설명은 한 번 읽으면 다시 보지 않았다.
급수를 어떻게 만들었는지는 아래 [급수는 무엇으로 만들었나](#급수는-무엇으로-만들었나) 참고.

초·한 중 아무 쪽이나 잡을 수 있다. 상차림은 대국을 시작하기 전에 양쪽 따로
고른다(마상상마·상마마상·마상마상·상마상마). 무르기·한수쉼·기권을 지원한다.

**설정은 두 겹으로 잠긴다.** 규칙·상차림은 첫 수를 두면 잠긴다. 쪽·급수·시계는
두는 동안 바꿀 수 있지만, **판이 끝나면 전부 잠겨서 새 대국을 눌러야 풀린다.**
끝난 판에서 시계를 바꾸면 양쪽 시계가 새로 차면서 시간패가 지워지기 때문이다. 규칙
줄 아래에 무엇이 잠기는지 한 줄로 적어 둔다.

**끝난 판은 되짚어 보기만 된다.** 판이 끝나면 무르기·다시가 이전·다음으로 바뀌고,
앞 국면으로 되짚어도 기물·한수쉼·기권이 잠겨 있다. '끝났다' 는 지금 보는 국면이
아니라 판 전체로 본다 - 외통으로 끝난 판을 첫 수까지 되짚어도 이어 둘 수 없다.

**새 대국·기권은 창을 띄워 한 번 더 묻는다.** 새 대국은 언제 눌러도 묻고, 창의 설명
한 줄만 상황마다 다르다(시작 전 · 두는 중이면 그 판이 사라진다 · 끝난 판은 목록에 있다).
둘 다 누르는 순간 판이 바뀌어 되돌릴 수 없다. 처음 초점은 '취소' 에 있어서 엔터를
습관처럼 눌러도 판이 끝나지 않는다. 예전에는 새 대국 버튼이 그 자리에서 붉게
바뀌기만 했는데 눈에 덜 띄어 묻는 줄 모르고 지나쳤고, 기권은 아예 묻지 않았다.

**기물은 눌러서도, 끌어서도 옮긴다.** 누르는 순간 갈 곳이 점으로 뜬다. 예전에는
끌어서 두는 것은 되는데 쥐고 있는 동안 아무 표시가 없었다 — 갈 곳은 눌러서 고를
때만 떴다. 초보일수록 기물을 쥐고 어디로 갈 수 있는지 보면서 옮기는데, 그때가
정작 아무것도 보이지 않는 순간이었다.

**내 차례에 내 기물만 들린다.** 예전에는 끌기가 아무 기물이나 들어서, 초를 잡고
있는데 한의 차가 손에 딸려 왔다가 놓으면 제자리로 돌아갔다. 상대 기물은 고른 내
기물로 잡을 때만 누를 수 있다.

**직전 수는 흰빛으로 짚는다.** 도착 자리는 기물이 가운데를 덮어서 출발 자리보다
크게(칸 0.8) 번지게 했다. 같은 크기였을 때는 도착 쪽이 가장자리만 희미하게 남아
어디로 갔는지 잘 안 보였다. 밝기는 출발 자리와 같다 - 한동안 도착 자리를 따로 진하게
칠했더니 기물 둘레에 흰 고리가 박혀 "두고 나서 말이 유독 더 밝다" 가 됐다.

**기물이 날아간다.** 눌러서 둔 수와 엔진이 둔 수는 기물이 출발 자리에서 도착 자리로
0.22초 동안 날아가고, 잡힌 기물은 닿을 즈음 사라진다. 순간이동처럼 옮기면 엔진이 어느
기물을 움직였는지 판을 훑어야 알았다. 끌어서 둔 수는 손으로 이미 옮겼으니 날리지 않고,
무르기·기보 이동도 날리지 않는다. 기기에서 '동작 줄이기' 를 켰으면 바로 옮긴다.

**장군·멍군을 외친다.** 방금 둔 수로 장군이 걸리면 판 가운데에 먹빛 상자로 "장군!" 이
1초 남짓 떴다 사라진다. 장군을 받은 쪽이 피하면서 되받아 장군을 부르면 "멍군!".
판을 누르는 것은 막지 않는다. 외통은 외치지 않는다 - 결과 창이 곧바로 뜬다. 궁의 붉은
테두리와 대국자 카드의 '장군' 칸은 장군이 풀릴 때까지 그대로 남는다.

**대국이 끝나면 결과 창이 뜬다.** 이겼는지 졌는지와 어떻게 끝났는지 한 줄, 그리고
**기보 보기**·**닫기** 두 버튼뿐이다. 예전에는 "복기 탭에서 볼 수 있습니다" 라고
적어두기만 해서 탭을 직접 찾아가야 했는데, 진 다음에 제일 알고 싶은 것이
'어디서 틀렸나' 다.

**규칙** — 표준·현대(카카오)·전통 중에 고른다. 승부가 어떻게 갈리는지를 정하는 것이라
대국 설정이고, 상차림과 같이 **판이 시작되면 잠긴다** — 두던 중에 승부 조건이
바뀌면 안 된다. 셋은 빅장과 긴 판을 끝내는 방법이 다르다.

| 규칙 | 빅장을 받으면 | 200수를 넘기면 | 양쪽이 한수쉼을 이어 두면 |
|---|---|---|---|
| 표준 (대회 규칙) | 점수로 가림 | 점수로 가림 | 점수로 가림 |
| 현대 (카카오) | 빅장 규칙 없음 | 점수로 가림 · 같은 수 되풀이 금지 | 점수로 가림 |
| 전통 | 무승부 | 끝나지 않음 | 무승부 |

- **빅장** — 두 궁이 한 세로줄에서 사이에 아무 기물 없이 마주 보는 것. 마주 보게 만든
  수가 빅장을 부른 것이고, 받은 쪽은 궁을 비키거나 기물로 막아 풀거나, **한수쉼을 두어
  빅장을 받는다**(판이 끝난다). 궁을 그 줄에 둔 채 옮기는 수는 없다. 빅장이 걸리면
  판 가운데에 "빅장!" 이 뜨고 받은 쪽 카드에 "빅장" 이 붙는다.
- **점수** — 판에 남은 기물 값의 합. 차 13, 포 7, 마 5, 상 3, 사 3, 졸·병 2(궁 빼고).
  나중에 두는 한에게 **덤 1.5** 를 얹어 주므로 점수가 같아 비기는 일이 없다.

빅장·양쪽 한수쉼이 나면 엔진은 둘 수를 하나도 내놓지 않는다. 예전에는 이것을 '수몰'
(둘 차례인 쪽의 패)로 읽어서, 전통 규칙에서 엔진이 비기려고 빅장을 받으면 비긴 판이
내 패로 적혔다. 이제 두 궁이 마주 봤는지, 한수쉼이 둘 이어졌는지를 보고 규칙대로 가린다.

**200수 제한** — 표준·현대에서는 양쪽 합해 200수를 넘기면 기물 점수로 승부를 가린다.
카카오장기가 쓰는 값이라 그대로 맞췄다. 여기가 어긋나면 그쪽에서 온 사람은 끝나야 할
판이 안 끝난다고 느낀다. 전통 규칙에는 점수제가 없으므로 걸리지 않는다.

**한(漢)의 덤이 점수 옆에 보인다.** 한은 후수라 1.5점을 미리 받는데, 그게 안 보이면
"왜 내가 앞서 있지" 하게 된다. 대국자 카드에 `덤 1.5` 로 붙여 둔다.

**시계** — **시계 없음**과 **5분**(제한시간 5분 + 초읽기 30초 3회) 두 가지이고,
기본은 5분이다. 예전에는 3·5·10·20분에 직접 입력까지 있었는데, 고를 것이 많으면
처음 온 사람은 무엇이 보통인지 모른다. 실제로 두는 길이가 5분대라 '쓴다 / 안 쓴다'
로 줄였다.

- 시계는 **첫 수가 놓여야 돈다.** 급수를 고르고 상차림을 맞추는 동안 시간이
  깎이면 곤란하기 때문이다.
- 제한시간이 바닥나면 초읽기로 넘어간다. 한 회 안에 두면 회수가 줄지 않고
  그 회가 처음부터 다시 찬다. 회를 넘기면 회수가 하나 줄고, 다 쓰면 시간패다.
- 기보를 되짚는 중(기보 끝이 아닐 때)이나 다른 모드에서는 멈춰 있다.
- **마지막 5초가 되면 숫자가 커지고 붉어진다.** "남은 시간을 잘 알려주지 않아
  시간패했다" 는 불만이 장기 앱마다 나온다. 숫자를 하나 더 띄우면 초읽기 표시와
  겹쳐 두 번 나오므로, 있던 숫자를 바꾸기만 한다.
- **초읽기 마지막 10초에는 1초마다 소리가 난다.** 판을 보고 있으면 숫자는 눈에
  들어오지 않는다. 내 차례에만, 다 쓰면 무언가를 잃는 시간(초읽기 한 회, 초읽기가
  없는 설정의 제한시간)에만 난다. 5분의 마지막 10초에는 울리지 않는다 - 끝나도
  초읽기로 넘어갈 뿐이다.

**소리** — 네 가지가 다르다. 켜고 끄는 버튼은 두지 않는다 - 끄고 싶다는 말이 실제로
나오면 그때 단다. 아직 아무도 쓰지 않는 앱에서 헤더 한 칸은 비싸다(`setSoundEnabled`
는 남아 있으니 다시 달 때는 부르기만 하면 된다).

| 동작 | 소리 |
|---|---|
| 기물을 집을 때 | 얕고 짧은 "톡" — 알을 판에서 살짝 드는 소리 |
| 기물을 놓을 때 | 단단한 "딱" |
| 기물을 잡을 때 | 두 번 닿는다 — 상대 알을 걷어내고 그 자리에 놓는다 |
| 초읽기 마지막 10초 | 1초마다 마른 나무를 두드리는 "똑". 마지막 5초는 한 음 높게 두 번("똑딱") |

음원 파일이 아니라 Web Audio 로 그 자리에서 만든다. 이유는 셋이다. 이 도구는
인터넷 없이도 돌아가야 하고, 녹음 파일은 출처와 라이선스를 달고 다니며,
합성이면 둘 때마다 높이를 조금씩 흔들어 기계 같은 반복을 피할 수 있다.

**훈수는 없다.** 두는 동안 엔진의 추천수를 보는 기능이 있었는데 뺐다. 켜 두면
대국이 아니라 받아쓰기가 된다. 엔진이 권하는 수와 형세는 판이 끝난 뒤
기보 탭의 복기에서 본다. 대국 중 엔진은 제 차례에만 돈다.

**대국 탭에는 수 목록이 없다.** 두는 중에 수 목록을 볼 일이 드물고(무르기·다시는
판 조작 줄에 있다), 끝난 판은 기보 탭에서 본다.

### 기보

**지난 판이 목록으로 남는다.** 카카오장기의 기보 타임라인을 따랐다. 한 칸에 상대
(`vs 16급`), 언제(`3시간 전`), 내가 잡은 쪽과 어떻게 끝났는지(`초 기권패`), 몇
수였는지, 그리고 끝난 모양을 작은 판으로 붙인다. 친구 초대·프로필·좋아요·댓글 같은
나눌 사람을 전제로 한 것은 뺐다.

- 판이 **끝나면 저절로** 들어간다(외통·수몰·기권·시간패·200수 점수).
- **끝나지 않은 판은 들어가지 않는다.** 두던 중에 새 대국을 누르면 그 판은
  사라진다(묻는 창이 미리 말한다). 한동안 '중단' 으로 넣었는데, 목록 이름이
  '기보' 인 이상 거기 선 것은 다 둔 판으로 읽혀서 끝난 판을 골라내기가 오히려
  어려웠다. 파일에서 불러온 끝나지 않은 기보는 그대로 '중단' 으로 든다.
- 끝난 뒤 무르고 다시 두어 다르게 끝나면 같은 줄이 바뀐다. 판마다 이름표(id)가
  있어서 한 판이 두 줄로 서지 않는다.

**목록은 쪽으로 나뉜다.** 한 쪽에는 화면에 스크롤 없이 들어가는 만큼 둔다(1440×900
이면 12판, 1920×1080 이면 15판, 1280×720 이면 9판). 아래 가운데에 쪽 번호가 서고,
쪽이 많으면 `1 … 4 5 6 … 9` 처럼 접는다. 한 판을 열었다가 목록으로 돌아오면 보던
쪽으로 온다. 폰은 화면 전체가 스크롤되어 잴 칸이 없으니 한 쪽 10판이다.

**한 판을 누르면 열린다.** 끝난 모양(마지막 수)에서 시작하고, 판 조작 줄로 처음부터
되짚는다. 기보 탭의 판은 읽기만 한다 - 둘 수 없다. 대국 탭에서 두던 판은 그대로
남아 있다. 두 탭이 각자 판을 들고 있어서 섞이지 않는다. 오른쪽 칸 맨 위 머리 줄
`[‹ 목록으로] 중단 · vs 6급 · 19분 전 [저장]` 로 목록에 돌아가고 기보 파일을 받는다(폰은
이 줄이 판 위에 선다).

**복기 결과는 그 판에 남는다.** 한 번 돌리면 다시 열 때 또 돌리지 않는다. 목록에
`복기함` 이 붙는다.

**파일로 저장·불러오기** — 연 판은 머리 줄의 "저장" 으로 JSON 을 받는다.
목록 위 "파일 불러오기" 는 그 파일을 목록에 한 판으로 넣는다(두던 판을 덮지 않는다).
넣기 전에 엔진이 수를 하나씩 짚어 규칙에 맞는지 본다. 맞지 않는 수가 있으면 몇 번째
수인지 알리고 넣지 않는다 - 화면은 그 수를 둔 판을 그리는데 엔진은 그 수를 받지 않아,
장군·복기가 다른 판을 두고 말하게 된다.
파일에는 누가 이겼는지만 있고 어떻게 끝났는지는 없어서, 불러온 판은 "승"·"패" 로만
적는다.

판을 남에게 건네는 길은 이 기보 파일 하나다. 주소 한 줄에 판을 담는 공유 링크가 있었는데
뺐다(버튼이 필요 없다는 판단 - 링크를 만들 길이 없으면 받는 쪽 코드도 쓸 데가 없다).

### 복기

기보를 처음부터 끝까지 한 수씩 엔진에게 물어보고, 실제로 둔 수와 견준다. 오른쪽 칸은
위에서부터 **형세 → 복기** 다.

**형세는 지금 보는 국면의 승률이다.** "초 69% · 한 31%" 와 두 색 막대 한 줄.
알파장기의 승률은 실제 대국 결과로 배운 신경망이 내는 값이지만, 이 엔진은 점수만
낸다. 그래서 점수를 곡선에 얹어 옮긴 **어림값**이다 - 졸 하나 앞서면 60%, 마 하나 69%,
차 하나 84%, 외통이 보이면 100%(아래 [손해를 장기 점수로 읽어도 되는 이유](#손해를-장기-점수로-읽어도-되는-이유)의
눈금에 맞췄다). 대국 중에는 점수를 매기지 않으므로 복기 전에는 형세가 뜨지 않는다.
화면에는 이 문단 대신 한 줄만 적는다 - "AI가 어림잡은, 지금 이길 가능성입니다."
왼쪽이 초라는 것은 바로 위에 초록 글자로 "초 69%" 라고 이미 적혀 있다.

한때 그 아래에 판 전체의 승률 흐름을 잇는 선 그래프가 있었다. **뺐다** - 수가 많아지면
100 폭 안에 점이 빽빽하게 들어차 선이 지저분해지고, 한 수 차이가 1px 도 안 돼서
'어디서 기울었나' 를 짚으라는 원래 목적이 되레 흐려졌다. 그래프가 겸하던 '그 수로
건너뛰기' 는 **판 조작 줄의 수 슬라이더**가 받았다. 오히려 이 자리가 맞다 - 그래프는
복기를 돌린 뒤에야 떠서 그 전에는 건너뛸 방법이 아예 없었다.

**복기는 판에 떠 있는 수 하나만 말한다.** 수는 판 조작 줄의 이전·다음과 수 슬라이더로
옮기고, 설명이 따라간다.

```
14사24  한의 6번째 수                    부정확
사를 앞으로 1칸 옮겼습니다.
승률        한 34% → 27%
AI의 수     32포35
그 뒤       초가 43졸33으로 마를 가져갑니다.
```

**기보 표기 아래에 풀어 쓴 한 줄이 붙는다.** `14사24` 는 좌표를 읽을 줄 알아야 뜻이
생긴다(앞 두 자리가 출발, 뒤가 도착이고, 각 자리는 `가로줄 세로줄` 순서다 - 가로줄은
위에서부터 1~9·0, 세로줄은 왼쪽부터 1~9). 장기를 처음 보는 사람에게는 네 자리 숫자일
뿐이라 복기가 무슨 수를 말하는지부터 막힌다. '앞/뒤' 는 **둔 쪽 기준**이다 - 판은
뒤집을 수 있어서 위아래가 보는 사람마다 다르지만, 앞뒤는 둔 쪽이 정해지면 하나로 정해진다.

**등급은 이름만 적는다.** 체스 기호(★ · ?! ? ??)는 뺐다 - 옆에 "악수" 라고 이미 적혀
있어 같은 말을 한 번 더 하는 것이고, 장기 두는 사람에게는 배경 지식을 요구한다.

손해는 점수 대신 둔 쪽의 승률이 얼마나 떨어졌는지로 말한다. AI의 수는 판에 파란 화살표로도
뜬다. 수 목록·일치율 성적표·"아쉬운 수" 오가기는 두지 않는다 - 한때 다 있었는데 읽을 것이 많아
정작 이 한 수의 설명이 묻혔다.

**등급은 넷, 잣대는 하나 - 둔 쪽 승률이 떨어진 폭이다.**

| 등급 | 언제 | 팽팽한 판이면 |
| --- | --- | --- |
| **최선수** | 엔진과 같은 수 | |
| **좋은 수** | 5%p 미만 | |
| **아쉬운 수** | 5%p 이상 | 졸 한 짝쯤 |
| **큰 실수** | 20%p 이상 | 마 한 짝쯤 |

화면에는 이름만 적는다 - 체스 기호(`?!` `?` `??` `★`)는 두지 않는다.

**한동안 다섯이었다**(부정확 · 실수 · 악수). 줄였다 - 나쁜 쪽을 셋으로 쪼개도 두는 사람에게는
'아쉽다' 와 '크게 잃었다' 둘로만 읽히고, 5%p 와 10%p 를 가르는 선은 재는 쪽의 사정이지
배우는 쪽의 사정이 아니다. 말도 바꿨다 - '부정확' 은 영어(inaccuracy)를 그대로 옮긴 말이고,
'악수(惡手)' 는 소리가 握手와 같아 처음 보면 엉뚱하게 읽힌다.

같은 5점 손해라도 팽팽한 판(61% → 39%)에서는 큰 실수, 이미 차 하나 앞선 판(90% → 78%)에서는
아쉬운 수다 - 앞의 것은 판을 내주고, 뒤의 것은 이기는 판이 그대로 이기는 판이다. 예전에는
점수 0.3 / 1.0 / 3.0 을 상대 급수에 따라 최대 세 배 늘려 썼는데, 같은 수가 상대에 따라 다른
등급이 됐고, 9단 눈높이는 팽팽한 판에서 승률 1.3%p 만 떨어져도 등급이 붙었다. 그 잣대로
매긴 예전 복기는 복기 전으로 읽어 다시 돌리게 한다.

**등급은 저장된 글자를 믿지 않고 읽을 때마다 다시 매긴다.** 승률 하락(`winDrop`)은 그대로
남아 있으므로, 등급 칸이 늘거나 줄어도 예전 복기가 지금 잣대로 읽힌다(다섯이던 때의
`mistake` 가 '아쉬운 수' 로 뜬다).

**깊이는 한 국면에 엔진이 얼마나 오래 들여다볼지다** - 빠름(10만) · 보통(50만) ·
정밀(200만 노드) 중에 고른다. 깊이를 바꾸면 등급도 바뀐다 - 빠름은 엔진이 덜 본 탓에
남은 잔값이 그대로 '승률이 떨어졌다' 로 읽혀서 괜찮은 수에도 부정확이 붙는다. '깊이' 는
엔진 쪽 말이라 화면에서는 그 아래에 한 줄로 풀어 둔다("복기는 한 수마다 엔진을 한 번씩
돌립니다. 정밀할수록 등급이 믿을 만해지고 그만큼 오래 걸립니다."). 복기한 뒤에도 깊이를
바꿔 다시 돌릴 수 있다. 중간에 그만두면 이번 복기는 남지 않는다 - 그 판은 복기 전(또는
지난 복기) 그대로다.

**복기는 두 번에 나눠 본다.** 1차로 기보 전체를 가볍게(10만) 훑고, **승률이 크게 움직인
수만 골라** 2차에서 고른 깊이로 다시 본다. 조용히 흘러간 수에 200만 노드를 쓰는 것은 거의
전부 버리는 일이다. 다시 볼 수는 기보가 길어져도 끝없이 늘지 않는다(수의 1/5, 다섯에서
열다섯 사이). 아무 수도 2%p 를 넘기지 않은 깨끗한 판이면 2차는 아예 돌지 않는다 - 자리를
채우려고 아무 일도 없던 수를 끌어오지 않는다.

**고른 수는 앞뒤 국면을 둘 다 다시 본다.** 등급은 두 국면의 승률 차이로 매기는데, 한쪽만
깊게 보면 깊이가 달라서 생긴 값 차이가 그대로 '손해' 로 읽힌다. 그래서 한 수 안에서는 늘
같은 깊이끼리 견준다 - 고른 수는 깊게 본 값끼리, 나머지는 훑은 값끼리.

몇 수를 다시 봤는지는 복기 칸 아래에 적는다("기보 전체를 훑고, 판이 갈린 5수를 다시 자세히
봤습니다"). 다시 볼 것이 없었으면 그 말도 적는다 - 아무 말이 없으면 고른 깊이로 전부 본
줄로 읽는다. **대가는 분명하다.** 조용히 흘러간 수는 얕게 본 값으로 남아서, 티 나지 않는
실수를 놓칠 수 있다.

**1차가 끝나면 바로 읽을 수 있다.** 모든 수에 설명이 붙은 뒤 2차가 도는 동안, 읽고 있는
수의 설명이 더 정확한 것으로 바뀐다. 다 끝나기를 기다리지 않는다(17수 기보에서 1차 2.3초,
전체 21.5초).

재 본 값(2026-10-01, 6코어 노트북 · 스레드 4개 · 40수 기보):

| 깊이 | 한 번에 다 보면 | 두 번에 나눠서 |
| --- | --- | --- |
| 빠름 | 4.4초 | (나누지 않는다) |
| 보통 | 21초 | 약 15초 |
| 정밀 | 1분 29초 | 약 45초 |

긴 기보일수록 더 벌어진다 - 1차는 수에 비례해 늘지만 2차는 열다섯 수에서 멈추기 때문이다.
100수 기보 정밀이 4분 12초에서 1분 28초가 된다.

설명을 무엇으로 만드는지는 아래 [복기는 무엇을 근거로 설명하나](#복기는-무엇을-근거로-설명하나) 참고.

### 설정과 두던 판이 브라우저에 남는다

급수·시계·규칙·내가 잡을 쪽·엔진 설정·복기 깊이·판 뒤집기를 localStorage
에 남긴다. 새로고침할 때마다 같은 것을 다시 고르지 않아도 된다.

**두던 판도 남는다.** 한 수라도 둔 판이면 기보와 보던 자리까지 되살린다. 폰에서
앱을 잠깐 나갔다 와도 두던 판이 그대로 있다.

다만 **한 수라도 둔 판일 때만** 되살린다. 상차림도 남기지 않는다 — 그건 설정이
아니라 판 자체다.

**끝난 판은 기보 목록에 최근 100판까지 남는다.** 복기까지 돌린 100수짜리 판이
4만 자 남짓이라 100판이면 브라우저 저장 한도(대개 500만 자)에 가깝다. 그래도
넘치면 오래된 판부터 덜어내고 남긴다.

**기권과 시간패도 되살린다.** 진 판을 새로고침해서 무를 수 있으면 안 된다.

**시계 자체는 남기지 않는다.** 새로고침한 동안 시간이 흘렀는지 알 길이 없어서
되살린 값이 맞다고 할 수 없고, 시계는 100ms 마다 바뀌어서 저장이 폭주한다.
이어서 열면 시계는 새로 찬다. 다만 시간패로 끝난 판이면 그 쪽 시계는 다 쓴
모습으로 되살린다 — 시계가 가득 찬 채 "시간패" 만 적혀 있으면 앞뒤가 맞지 않는다.

**읽어온 값은 믿지 않는다.** localStorage 는 사람이 직접 고칠 수 있고, 예전 판에서
저장해 둔 값이 지금은 없는 급수일 수도 있다. 그래서 값마다 "지금도 쓸 수 있는
모양인지" 를 확인하고 아니면 기본값으로 되돌린다. 이상한 값이 들어가도 다음
실행에서 저절로 낫는다 — 이게 없으면 사용자가 빠져나올 방법이 없다.

저장이 막힌 브라우저(사생활 보호 모드, 저장 차단)에서도 앱은 그냥 돈다. 읽기·쓰기
실패는 조용히 넘기고 기본값으로 간다.

### 어느 모드에서나

**대국 상태** — 장군을 맞으면 궁이 붉게 뛰고 그쪽 대국자 카드에 "장군" 이 붙는다.
빅장이 걸리면 받은 쪽 카드에 "빅장" 이 같은 모양으로 붙는다.
외통이면 카드에 "승"·"외통패" 를 적고 더 둘 수 없게 막는다. 장기에는 한수쉼이 있어서
외통이어도 합법수가 0이 되지 않으므로, "장군인데 한수쉼 말고는 둘 게 없음" 을
기준으로 판정한다.

판 위에는 배너를 띄우지 않는다. 판 크기가 남은 높이로 정해져서, 배너가 뜰 때마다
판이 그만큼 줄었다 늘었다 했다. 규칙에 맞지 않는 판은 헤더에 "잘못된 판" 으로 건다(자리를
차지하지 않는다). 한 번 말하고 마는 알림은 떠 있게 두지 않고 누른 자리에서 말한다 - 불러온
판은 목록 맨 위 카드가 잠깐 도드라지고, 못 읽은 까닭은 "파일 불러오기" 옆에 한 줄로 남는다.
떠 있는 알림은 어디에 띄워도 오른쪽
칸의 무언가(복기 설명, 쪽 번호)를 가렸다.

**툴팁은 두지 않는다.** 마우스를 올려야 보이는 설명은 폰에서 볼 수 없고, 올릴 때마다 떠서
성가셨다. 화면 읽기 프로그램에 필요한 말만 보이지 않는 글자로 남겼다.

**글자는 고를 수 있다. 버튼과 판만 막는다.** 한동안 화면 전체를 막아 뒀었다 - 캐럿
브라우징(F7)이 켜진 크롬·엣지에서 누른 자리마다 캐럿이 깜박이는 것을 잡으려던 것인데,
그러면서 복기 설명이나 판 정보처럼 **옮겨 적을 일이 있는 글까지 베낄 수 없게** 됐다.
빈 선택이 생기는 것은 누르는 것들이므로 거기만 막는다. **캐럿은 따로 숨긴다** -
`body` 에 `caret-color: transparent`, 값을 적는 칸(`input`·`textarea`)만 되살린다.
캐럿이 깜박이는 것과 글자를 고르는 것은 따로 끌 수 있었다. 애초에 그 캐럿은 캐럿
브라우징이 켜져 있을 때만 그려지므로 진짜 해결은 F7 을 한 번 더 누르는 것이고,
이 규칙은 모르고 켜 둔 채로 쓰는 사람을 위한 보험이다.

**상차림** - 마상상마(원앙마), 상마마상(양귀마), 마상마상(오른귀마),
상마상마(왼귀마). 뒷줄에 마와 상이 놓인 순서를 자기 왼쪽부터 그대로 읽은
이름이다. 초는 아래에 앉으니 a→i, 한은 위에 앉으니 i→a 로 읽으므로 같은
차림은 양쪽이 같은 이름으로 불린다. 양쪽이 따로 고르고, 지금 판이 어떤
차림인지도 되읽어서 표시한다.
`면상`은 별도의 차림이 아니라 귀마 차림에서 상을 면자리로 올리는 포진이라
프리셋에 없다.

**업데이트 내역** — 헤더 오른쪽 끝의 `업데이트 내역` 을 누르면 **가운데에 창이
뜬다**(결과 창·확인 창과 같은 틀, Esc 로 닫힌다). 두던 판은 그대로 있다. 지금
버전은 창 안에서 날짜와 나란히 적혀 있고, 제보할 때도 자동으로 붙는다.

한동안 이것이 **앱과 따로 서는 두 번째 쪽**(`/updates/`)이었다. 엔진도 React 도
쓰지 않는 글 한 장이라 뜨는 것이 빨랐지만, 몇 줄 읽고 닫을 글 때문에 새 탭이 열리고
두던 화면을 떠나야 했다. 창으로 옮기면서 그 쪽과 전용 스타일은 지웠다. 내용과 버전은
`src/updates/log.ts` 한 곳에 있다 - 두 군데 적으면 화면에 뜨는 버전과 제보에 붙는
버전이 어긋난다.

글 셋은 독자가 다르다. **커밋 메시지**는 나중의 나에게 무엇을 왜 고쳤는지,
**`docs/DECISIONS.md`** 는 코드를 보는 사람에게 왜 그렇게 정했는지,
**업데이트 내역**은 장기 두는 사람에게 무엇이 달라졌는지를 말한다. 그래서 거기만
`~해요` 로 적고 기능 이름 대신 화면에서 달라지는 것을 쓴다.

**제보 버튼** — 화면 오른쪽 아래에 떠 있다. 누르면 제보 창구가 새 탭으로 열리는데,
**버전·창 크기·브라우저·지금 보고 있는 판이 이미 적힌 채로** 열린다(구글 폼의 미리 채우기).
"말이 안 움직여요" 만 오면 아무것도 못 하는데, 제보는 몇 건 오지 않고 되물으면 절반은
답이 오지 않는다. 붙여넣기를 시키면 절반은 그냥 비워 둔 채 보낸다 - 보내는 사람에게 할
일을 하나라도 덜 주는 쪽이 받는 쪽에 이롭다.

적는 글은 **두 줄**이다. 보내는 사람이 그 칸을 보게 되므로 짧아야 한다.

```
장기 AI v0.1.0 · 크롬 154 · 윈도우 · 창 1440×900
기보 · 42수 · rnba1abnr/4k4/1c5c1/...
```

긴 `userAgent` 를 그대로 적던 것을 브라우저 이름 한 토막으로 줄였다 - 자기가 적은 말보다
긴 알 수 없는 글이 폼에 들어 있으면 지우거나, 보내기를 그만둔다. 모르는 브라우저는 그대로
적는다(드물고, 드물 때가 제일 궁금하다). **받는 칸은 장문형이어야 한다** - 단답형은 줄바꿈을
지워 버려서 두 줄이 붙는다. 이름표(`VITE_FEEDBACK_ENTRY`)가 없으면 빈 폼만 연다.
`VITE_FEEDBACK_URL` 을 비워 두면 버튼 자체가 뜨지 않는다([환경 변수](#환경-변수)).

글자는 `피드백 및 버그 제보`, 높이 56(좁은 창에서는 48)으로 **화면에서 가장 큰 버튼**이다.
한동안 `버그 제보`로 짧게 뒀는데 그 글자는 받을 것을 좁힌다 - "이건 버그는 아닌데" 싶은
말은 보내지 않게 되고, 쓰는 사람이 바라는 것은 대개 버그가 아니라 그쪽이다.

이건 **떠 있는 것을 두지 않는다는 규칙의 유일한 예외**다. 칸 안에 자리를 내주지는
않는다 - 처음에는 가리지 않게 오른쪽 칸과 기보 목록 아래에 64 여백을 뒀는데, 그러자
**기보 목록이 한 쪽에 들어가는 판 수가 12 에서 9 로 줄었다**(목록은 '스크롤 없이 들어가는
만큼' 을 한 쪽으로 잡는다). 떠 있는 것 하나 때문에 목록의 짜임이 바뀌면 안 된다. 대신
글자를 짧게(`버그 제보`, 91px) 둬서 덮는 넓이를 줄였다 - `피드백 · 버그 제보`(142px)로
뒀을 때는 1280×720 에서 상차림 마지막 칸을 덮었다.

**기보 파일 형식** — 시작 국면과 수순, 평가치, 그리고 누가 어느 쪽을 어떤
급수로 잡았는지와 승부 결과까지 JSON 으로 담는다(`janggi-board/2`).
승부는 이긴 쪽·무승부·끝나지 않음 가운데 하나로 적는다.
급수와 결과가 없던 첫 형식(`janggi-board/1`)도 그대로 읽는다.

**키보드** — `←` `→` 앞뒤로, `Home` `End` 처음·끝, `F` 판 뒤집기.

## 화면 배치

페이지는 스크롤되지 않는다. 화면 높이를 그대로 받아 쓰고, 넘치는 것은 오른쪽
패널 칸이 자기 안에서 스크롤한다. **판의 크기는 폭이 아니라 남은 높이가 정한다.**
세로가 짧은 창에서도 판 전체가 잘리지 않고 들어가야 하기 때문이다.

**대국자 카드는 오른쪽 칸 맨 위에 두 장이 포개진다**(상대 위, 나 아래 - 판과 같은
순서). 윗줄에 누구·차례(장군·승패)·남은 시간, 아랫줄에 **시간 막대**·기물 점수를
두고, **둘 차례인 쪽만** 흰 바탕으로 띄운다. 시간 막대는 예전에 카드 아래 모서리에
4px 로 깔려 있어서 있는 줄도 몰랐다. 대국 중에는 잡은 기물보다 남은 시간이 급해서
잡은 기물 자리를 막대에 내줬다. 시계를 끈 판과 기보 탭의 지난 판에는 잡은 기물이 선다.

**대국 탭의 오른쪽 칸은 판 아래 끝에 맞춰 선다.** 예전에는 내용만큼만 서서 판이 큰
화면일수록 칸 아래가 비었다(1920×1080 에서 224px). 남는 높이는 대국자 카드 두 장이
나눠 갖고, 카드가 넉넉해지면(두 장 합쳐 320 이상) 시계가 한 줄을 따로 차지하며 40px 로
커진다. 설정이 판보다 긴 낮은 창에서는 카드가 기본 높이로 서고 칸 안에서 스크롤한다. 예전에는 판 위아래에 한 줄씩 붙었는데,
판 폭만큼 긴 줄에 이름은 왼쪽 끝·시계는 오른쪽 끝이라 눈이 오갔고, 두 장이 판에서
세로 92px 을 가져갔다. 옮기고 나서 1440×900 에서 판이 659×732 → **741×824** 가 됐다.

폰은 오른쪽 칸이 판 아래로 내려가서, 카드를 옮기면 오히려 판에서 멀어진다. 그래서
폰에서는 예전처럼 판 위아래에 한 줄씩 붙는다. 그때 카드를 판과 같은 너비로 맞추려고
판을 다 그린 뒤 너비를 재서(`ResizeObserver`) 넘긴다. CSS 로 카드 너비를 판에
맞추면(`width: fit-content`) 카드가 판의 너비를 정해버려서 서로 물고 돈다.

화면이 작을 때는 이렇게 물러선다.

| 조건 | 하는 일 |
|---|---|
| 창이 좁아 판이 폭에 걸릴 때 | 판을 판 비율 그대로 줄여 위에 붙인다. 양끝 여백은 창 폭의 4%(32~64px) |
| 세로 780px 이하 | 페이지 여백과 카드 사이 틈을 더 좁힌다 |
| 판 자리가 280px 미만 | 판을 더 줄이지 않고 판 칸 안에서 스크롤한다 |
| 가로 900px 이하 | 풀스크린을 포기하고 위아래로 쌓아 스크롤한다 |

판에 높이를 한 줄이라도 더 주려고 이렇게 했다.

- **모드 탭을 제목 줄 안에 넣었다.** 설명이 붙은 카드 세 장이 한 줄을 통째로
  차지해 세로 57px 을 먹고 있었다. 설명은 화면 읽기용 글자로만 남겼다.
- **판 안쪽 여백을 56 → 46 으로 줄였다.** 격자가 판 넓이에서 차지하는 몫이
  83% 에서 86% 로 늘었다. 좌표 숫자와 가장자리 기물이 겨우 스치지 않는 선이다.
- **버튼 줄을 오른쪽 칸으로 옮겼다.** 무르기·다시·판 뒤집기·한수쉼이 판 아래에
  붙어 44px 을 가져가고 있었는데, 정작 가로는 1440px 화면에서 판 옆에 350px 이
  놀고 있었다. 세로는 모자라고 가로는 남는 배치였다.
- **대국자 카드를 44 → 38px 로, 카드-판 사이 틈을 10 → 8px 로 줄였다.**

1440×900 기준으로 판이 575×633 에서 **646×718** 이 됐다.

**글자는 어디서나 16px 아래로 내려가지 않는다.** 예전에는 11~14px 짜리 잔글씨가
곳곳에 있었다. 화면은 촘촘해 보이지만 판 앞에 앉아 한 판 두는 동안 읽기에는
작다. 화면이 작다고 글자까지 줄이지는 않는다 — 좁아지면 여백을 줄인다.

색은 **화이트 한 가지**다. 장기판 자체가 밝은 나무색이라, 판 둘레가 어두우면
판만 떠 보이고 눈이 아프다.

## 급수는 무엇으로 만들었나

한 급수는 **(Skill Level, 노드 수)** 한 쌍이고, 18급부터 9단까지 27칸이다.
표는 `src/engine/levels.ts` 에 있다. 어떻게 여기까지 왔는지는 전부 엔진에 직접
물어보고 1,120판을 붙여본 결과다.

### UCI_Elo 는 쓰지 않는다

엔진에 `UCI_LimitStrength` / `UCI_Elo`(500~2850) 옵션이 있어서 이것부터 시험했다.
장기 변형에서 Elo 를 바꿔가며 같은 국면을 돌린 결과는 이랬다.

```
Elo  500 | i4h4 b1c3 i4h4 b1c3 | depth≈15
Elo 1000 | a4b4 a4b4 i4h4 i4h4 | depth≈15
Elo 1800 | h1g3 b1c3 b1c3 b1c3 | depth≈15
Elo 2850 | a4b4 b1c3 b1c3 b1c3 | depth≈16
```

500 이나 2850 이나 똑같이 멀쩡한 수를 낸다. 이 환산표는 체스용으로 맞춰진 것이라
장기에는 눈금이 붙지 않는다. 숫자만 그럴듯하고 실제로 약해지지 않아서 버렸다.

### Skill Level 은 먹힌다

```
초기 국면에서 여섯 번씩 (300ms)
  Skill  20 | 서로 다른 수 1/6   ← 여섯 번 다 같은 최선수
  Skill   0 | 서로 다른 수 3/6
  Skill -20 | 서로 다른 수 2/6   ← 최선수를 아예 안 고름
```

종반 국면에서는 더 선명하다. 차를 쓸 수 있는 자리에서 Skill -20~-5 는 여덟 번 중
여덟 번 궁만 제자리에서 꼬물거렸고(`e1d1` `e1f1` `e1e1`), Skill 10~20 은 여덟 번 중
일고여덟 번 차를 움직였다.

### 시간이 아니라 노드로 자른다

`go nodes N` 은 정확히 N 노드에서 끊긴다 — 요청 1,000 → 실제 1,000, 요청 100만 →
실제 1,000,679. 시간으로 자르면 빠른 PC 의 3급이 느린 PC 에서는 5급이 된다.
노드로 자르면 어느 기기에서나 같은 급수다.

다만 약한 급수는 2천 노드를 눈 깜짝할 새에 보고 끝내므로, 최소 생각 시간
(`MIN_THINK_MS`)을 따로 둔다. 안 그러면 대국 같지가 않다.

### 27칸의 간격은 자가대국으로 쟀다

급수를 27칸으로 자르면 이웃한 두 칸의 차이는 아주 작다. 그 차이를 자가대국으로
직접 확인하려면 한 쌍에 수백 판이 필요하고, 쌍이 26개면 며칠을 부어도 모자란다.
그래서 순서를 뒤집었다.

1. 두 손잡이를 **하나의 강도 곡선**으로 묶는다. `t` 는 0(가장 약함)에서
   1(가장 셈)로 가는 눈금이다.

   ```
   Skill Level = -20 + 40t
   노드        = 1,500 · (5,000,000 / 1,500)^t
   ```

2. 그 곡선 위에 서로 확실히 구분되는 **기준점 13개**를 찍고, 이웃 쌍과 한 칸
   건너뛴 쌍끼리 실제로 붙인다.
3. 승패를 **Bradley-Terry** 로 풀어 기준점마다 레이팅을 낸다.
4. 그 레이팅 눈금 위에 급수 27칸을 앉힌다.

스크립트는 `scripts/ladder-selfplay.mjs` 다. 6코어 PC 에서 네 판씩 동시에 돌려
**85분 동안 1,120판**을 뒀다. 상차림 16가지를 돌려가며 색을 번갈아 잡았다.

**이웃한 기준점끼리**

| 대결 | 위쪽 승률 | 판수 |
|---|---|---|
| C1 vs C0 | 53% | 100 |
| C2 vs C1 | 52% | 100 |
| C3 vs C2 | 54% | 100 |
| C4 vs C3 | 63% | 100 |
| C5 vs C4 | 59% | 85 |
| C6 vs C5 | 86% | 47 |
| C7 vs C6 | 69% | 26 |
| C8 vs C7 | 100% | 14 |
| C9 vs C8 | 81% | 8 |
| C10 vs C9 | 100% | 5 |
| C11 vs C10 | 75% | 4 |
| C12 vs C11 | 88% | 4 |

**한 칸 건너뛴 기준점끼리** — 65% · 61% · 66% · 73% · 94% · 87% · 100% · 100% ·
100% · 88% · 88%

**23쌍 전부 위쪽이 앞섰다. 역전이 하나도 없다.**

- 이웃 쌍을 전부 합치면 593판에서 위쪽 승률 **61.0%**
- 한 칸 건너뛴 쌍은 527판에서 **72.6%**

솔직하게 적어두면, 아래쪽 쌍을 하나씩 떼어놓고 보면 100판에 53%·52%·54% 라
그 한 쌍만으로는 통계적으로 유의하지 않다(표준오차가 5% 다). 하지만 23쌍이 모두
같은 방향으로 나올 확률은 동전 던지기로 1,200만 분의 1이고, 한 칸 건너뛴 쌍은
65~66% 로 분명히 갈린다. **한 칸 차이는 작고 두 칸 차이는 확실하다** — 눈금이
이 정도면 촘촘한 것이다. 한 칸 차이가 압승이면 27칸으로 나눌 이유가 없다.

**기준점 레이팅** (가장 약한 쪽을 0점으로)

| 기준점 | Skill | 노드 | 레이팅 | 판수 |
|---|---|---|---|---|
| C0 | -20 | 1,500 | 0 | 200 |
| C1 | -17 | 2,700 | 40 | 300 |
| C2 | -14 | 4,900 | 78 | 400 |
| C3 | -11 | 8,700 | 108 | 400 |
| C4 | -8 | 15,700 | 195 | 340 |
| C5 | -6 | 28,000 | 276 | 263 |
| C6 | -3 | 51,000 | 581 | 145 |
| C7 | 0 | 91,000 | 673 | 81 |
| C8 | 3 | 165,000 | 1,184 | 45 |
| C9 | 6 | 298,000 | 1,364 | 27 |
| C10 | 9 | 505,000 | 1,651 | 19 |
| C11 | 12 | 900,000 | 1,714 | 12 |
| C12 | 15 | 1,600,000 | 1,925 | 8 |

점들을 매끄럽게 펴면 **R(t) = -13 + 2,896·t²** 이다(가중 R² = 0.966).
아래쪽은 평평하고 위로 갈수록 가파르다. 약한 설정끼리는 둘 다 실수를 해서
승패가 뒤집히고, 그래서 점수 차이가 작게 나오기 때문이다.

### 27칸을 어디에 앉혔나

간격을 `t` 가 아니라 **레이팅**으로 고르게 잡았다. `t` 로 고르게 나누면 실제
실력 차이가 아래쪽은 촘촘하고 위쪽은 듬성듬성해진다.

두 구간으로 나눴다.

| 구간 | 범위 | 한 칸 |
|---|---|---|
| 급 (18급~1급) | t=0 부터 한 수 15만 노드까지 | 약 **55점** |
| 단 (1단~9단) | 그 위부터 끝까지 | 약 **225점** |

왜 한 줄로 고르게 펴지 않았나. 엔진끼리의 레이팅은 약한 쪽에서 납작해지는데,
그 납작함을 그대로 믿고 펴면 급수 대부분이 사람이 이길 수 없는 구간에 몰린다
(실제로 해보니 11급이 한 수에 10만 노드를 보게 됐다). 하지만 사람 눈에는
Skill -20(기물을 그냥 내준다)과 Skill -8(포진은 갖춘다)이 전혀 다른 상대다.
그래서 사람이 이길 수 있는 아래쪽에 급 18칸을 몰아주고, 그 위는 단 9칸이 훑게 했다.

**이 방법의 한계도 적어둔다.**

- 곡선이 `a + c·t²` 꼴로 정해지면, 레이팅을 고르게 나눈 지점은 `t = √(k/n)` 이
  되어 **a 와 c 가 무엇이든 같은 자리**가 나온다. 그러니 1,120판이 급수의 위치를
  직접 찍어준 것은 아니다. 1,120판이 정한 것은 세 가지다 — 사다리가 실제로
  단조롭다는 것, 강도가 자라는 **모양**(자유 2차식은 t=0 에서 아래로 꺾여
  쓸 수 없었다), 그리고 **한 칸이 몇 점짜리인가**.
- 위쪽 기준점(C9~C12)은 한 판에 수 분씩 걸려 8~27판밖에 못 뒀다. 단 구간의
  간격은 급 구간만큼 단단하지 않다.
- 2단 위쪽(t > 0.87)은 아예 붙여보지 못했다. 같은 곡선을 연장해서 쓴다.

같은 자료를 다시 계산하려면:

```bash
node scripts/ladder-selfplay.mjs --from ladder-result.json
```

### 이름에 대하여

**공인 급수가 아니다.** 장기 급수 이름을 빌려 왔을 뿐 이 앱 안에서만 쓰는 눈금이고,
화면에도 그렇게 적어뒀다. 실제 18급이 여기 18급을 이길지는 재본 적이 없다.
붙여본 것은 엔진끼리이지 사람과가 아니다. 급수마다 붙은 한 줄 설명도 그 설정의
'느낌' 을 적은 것이지 측정한 값이 아니다.

## 복기는 무엇을 근거로 설명하나

설명은 전부 **엔진에서 나온 사실만** 엮어서 만든다. 쓰는 재료는 넷이다.

- 엔진이 고른 최선수와 그 이후 수순
- 실제로 둔 수
- 두기 전과 둔 뒤의 평가치 차이 (= 손해)
- 그 수 이후 상대가 무엇을 잡는가

포진 이름이나 전략 해설은 붙이지 않는다. 지어내게 되고, 복기에서 틀린 설명은
아무 설명도 없는 것보다 해롭다.

### 손해를 장기 점수로 읽어도 되는 이유

초기 국면에서 기물을 하나씩 빼고 40만 노드로 평가시켜 눈금을 재봤다.

| 뺀 기물 | 장기 점수 | 엔진 점수 |
|---|---|---|
| 병 | 2점 | +2.30 |
| 마 | 5점 | +4.54 |
| 포 | 7점 | +5.20 |
| 차 | 13점 | +9.42 |

낮은 쪽에서는 엔진 점수 1.0 이 대략 장기 1점이고, 위로 갈수록 눌린다. 이 눈금으로
점수를 승률에 옮긴다(`winChance`, `1 / (1 + e^(−0.18·점수))`: 병 하나 60%, 마 하나 69%,
차 하나 84%). 등급은 그 승률이 떨어진 폭으로 나눈다.

| 둔 쪽 승률 하락 | 등급 |
|---|---|
| 엔진과 같은 수 | 최선수 ★ |
| 5%p 미만 | 좋은 수 |
| 5 ~ 10%p | 부정확 ?! |
| 10 ~ 20%p | 실수 ? |
| 20%p 이상 | 악수 ?? |

손해를 기물로 옮길 때는 경계가 흐릿해서(마 4.54 vs 포 5.20) 폭을 넓게 잡고
"마나 포 한 짝쯤" 처럼 말한다.

외통 점수는 그대로 빼면 손해가 수백이 되므로 ±20 으로 자른다. 이기는 외통에서
더 빠른 외통으로 바뀐 것뿐인데 악수로 찍히면 곤란하기 때문이다.

## 좌표와 기보

장기 기보 방식을 그대로 쓴다. 세로줄은 왼쪽부터 1~9, 가로줄은 위에서부터 1~9 와
0(열째 줄). 좌표는 **가로줄을 먼저** 읽는다. 그래서 초의 궁 자리는 95, 한의 궁
자리는 25다. 한 수는 `출발좌표 기물 도착좌표` 로 적는다 — 예: `03마84`. 기물명은
한글이다(차·포·마·상·사·졸·병·궁).

**판에는 좌표 숫자를 그리지 않는다.** 실물 장기판에 없기도 하고, 숫자 자리를
비우면 그만큼 격자가 커진다(판 넓이의 86% → 89%).

기보의 "75졸65" 가 어디인지는 그 수로 옮겨 가면 판의 직전 수 표시로 보인다.

엔진은 내부적으로 체스식 좌표(a1~i10)를 쓰고, `src/janggi/notation.ts` 가 둘
사이를 옮긴다.

## 기물과 판

실물 장기알은 상아빛 팔각 나무토막이고, 옆면 두께가 보인다. 그래서 기물을 세 겹으로
그린다.

1. **옆면** — 같은 팔각형을 아래로 조금(반지름의 10%) 밀어 어둡게. 이게 두께다.
2. **테** — 위에서 빛을 받는 빗면. 왼쪽 위가 밝고 오른쪽 아래가 어둡다.
3. **윗면** — 글자를 새기는 평평한 면.

여기에 바닥 그림자(`feDropShadow`)를 깔아야 판 위에 '얹힌' 것처럼 보인다.
그림자와 빛깔은 SVG `<defs>` 에 미리 정의해 두어야 해서 `PieceDefs` 로 빼 놓았고,
기물을 그리는 `<svg>` 마다 한 번씩 넣는다. 카드에 늘어놓는 잡은 기물처럼 아주
작게 그릴 때는 빗면도 그림자도 보이지 않으므로 단색으로 그린다(`flat`).

판은 밝은 대나무색에 아주 옅은 세로 결을 깔았고, 격자선은 불투명하게 올렸다.
예전에는 투명도 0.72 라 흐릿했는데, 실물 장기판의 선은 또렷하다.

글자는 지름의 0.58 에서 **0.64** 로 키웠다. 작으면 멀리서 무슨 기물인지 안 보인다.

## 기물 글자

실물 장기판처럼 **초(楚)는 초서체(흘림), 한(漢)은 해서체(정자)** 로 새긴다.
색도 실물대로 초가 초록, 한이 빨강이다. 한국 장기 앱 중에는 초를 파랑으로
쓰는 것도 있지만, 초서체 글자를 실물 기준으로 만들어 뒀으므로 그쪽을 따랐다.
유니코드에는 초서 글자가 따로 없어서 폰트로는 이 구분을 낼 수 없다. 그래서
글자를 SVG 도형으로 들고 있다(`src/janggi/glyphs.ts`). 출처는 `NOTICE.md` 참고.

기보는 한글로 적는다 — `03마84` 처럼. 예전에는 한자(`03馬84`)였는데, 앱 글꼴(Pretendard)에
장기 한자가 둘뿐이라 나머지를 기기의 고딕에서 가져와 기기마다 모양이 달랐다. 브라우저에
남은 예전 판은 읽을 때 한글로 바꾼다.

기보 목록의 작은 판은 **어느 화면에서나 기물 글자를 둔다**(7px 남짓이다). 한동안
밀도가 낮은 화면(대개 컴퓨터)에서는 글자를 빼고 진영색 점으로 칠했는데, 점만 찍힌
판은 어느 편 기물이 어디 있는지만 알려 줄 뿐 장기판으로 읽히지 않았다 - 목록에서 어떤
판이었는지 알아보는 데 쓸모가 없었다. 조금 흐린 글자가 또렷한 점보다 낫다.

## 진영 표기

Fairy-Stockfish 의 대문자(White)가 **초(楚)**, 소문자(Black)가 **한(漢)** 이다.
초가 선수이고 한이 1.5점 덤을 받는 장기 규칙과 맞다. 화면에서는 초가 초록,
한이 빨강이며 초가 아래쪽에 앉는다(판 뒤집기로 바꿀 수 있다).

## 라이선스

**GPL v3 이상**(`LICENSE`). 엔진(Fairy-Stockfish)이 GPL v3 이고, 빌드 결과물에
`stockfish.wasm` 이 들어가 방문자마다 전달된다. UCI 로만 주고받으니 "별개 저작물" 로 볼
여지도 있지만, 같은 페이지에 올려 함수로 부르는 구조라 다툼의 소지가 있다. 비상업
프로젝트라 GPL 로 내도 잃는 것이 없어 **논쟁 자체를 없앴다.** AGPL 은 쓰지 않는다 -
엔진이 GPL v3 이고 탐색이 전부 브라우저에서 돌아 서버 쪽 조항이 걸릴 데가 없다.

**예외 하나.** `src/janggi/glyphs.ts` 의 기물 글자는 **CC BY-SA 3.0** 이다. 위키미디어
공용 File:Janggi.svg 의 2차적 저작물이라 프로젝트 라이선스와 별개로 그 조건을 유지해야
한다. 파일 머리말과 `NOTICE.md` 에 적어뒀으니 **지우지 말 것.**

### 고지는 배포본에 함께 실린다

GPL v3·CC BY-SA 3.0·OFL 1.1 모두 고지가 배포물에 따라붙을 것을 요구한다. 번들러는 주석을
지우므로 `npm run fetch-engine` 이 `public/` 아래로 복사해 둔다(`.gitignore` 로 제외된
생성본이다. 원본은 `NOTICE.md` 와 엔진 패키지 하나씩이라 고칠 곳이 한 군데다).

| 올라가는 곳 | 무엇 |
| --- | --- |
| `/licenses/` | 제3자 고지 쪽 (= `NOTICE.md`) |
| `/licenses/GPL-3.0.txt` | GPL v3 전문 (엔진과 이 앱) |
| `/engine/AUTHORS` | 엔진 저작자 목록 |

고지를 `.txt` 가 아니라 **쪽으로** 만드는 까닭이 있다. 서버가 `Content-Type: text/plain`
만 보내고 charset 을 안 붙이면 브라우저가 UTF-8 로 읽지 않아 **한글이 전부 깨진다**(실제로
겪었다). 쪽 안에 `<meta charset>` 을 박아 두면 어디에 올리든 읽힌다. 남은 `.txt` 둘은
`vercel.json` 이 charset 을 붙인다.

앱에서는 **업데이트 내역 창 아래의 '오픈소스 고지'** 로 연다.

### 저장소를 공개할 때

GPL v3 는 배포본을 받은 사람이 소스를 받을 수 있어야 한다고 요구한다. 웹에 올리면
방문자 모두가 받는 사람이다. **저장소를 공개로 돌리는 것이 가장 간단하다.** 공개 전에
`.env.local` 이 커밋된 적이 없는지 확인할 것(`git log --all -- .env.local` 이 비어야 한다).

### 남은 것 — 신경망

장기 신경망에는 **라이선스가 명시되어 있지 않다.** 배포처는 "2026년 이후 날짜의 망은
CC0" 라고만 밝히는데 우리 망은 2025-07-31 이다. 공식 배포처가 공개했고 이 망을 내장한
릴리스까지 있어 실무상 위험은 낮다고 보고 쓰지만, 허락이 명시된 상태는 아니다.
상위 프로젝트에 문의하고, 2026년 이후 망이 나오면 갈아탄다. (`NOTICE.md` 2번)
